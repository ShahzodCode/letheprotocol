# Commands, tests and performance tooling
Read this when you run the game, write or run a test, take screenshots or measure performance. Numbers from measurements live in [performance.md](performance.md).

## Commands
- Run the game: open the folder in the Godot editor and press F5, or `godot --path .` (`-- --sandbox` starts the sandbox mission: enemies respawn)
- Headless checks (fast, ~5 s, exit code 1 on failure): `godot --headless --fixed-fps 120 --path . -- --selftest`
- Screenshots under a virtual display (needs `xvfb-run`): `xvfb-run -a -s "-screen 0 1280x720x24" godot --path . --rendering-driver opengl3 --resolution 1280x720 -- --shots /tmp/shots`
- Any test script alone: `godot --headless --fixed-fps 120 --path . -- --script res://tests/mine.gd` (a Node with `run(main)`; handy for debugging one feature, e.g. instantiate selftest.gd, set its `main` / `player` / `all` and `await` one test function).
- First run after adding assets or a new `class_name` script: `godot --headless --path . --import` (refreshes the global class cache)
- Windows: `Godot.exe` is a GUI-subsystem build, so shell redirection captures nothing; start it with PowerShell `Start-Process -Wait -RedirectStandardOutput out.txt -RedirectStandardError err.txt` and read the files. Screenshots work without xvfb: `Godot.exe --path . --rendering-driver opengl3 --resolution 1280x720 -- --shots <dir>` (use `.shots`, dot folders are ignored by the importer).
- Godot is not installed by default in the cloud container: download the Linux build that matches the project (4.7.x; the old note said `Godot_v4.3-stable_linux.x86_64.zip`, which is OUTDATED, `project.godot` has features "4.7") from github.com/godotengine/godot-builds releases.

## Testing
Tool scripts in tests/ (run through `-- --script res://tests/<name>.gd`): `char_view.gd` (renders enemy kinds / civilians in poses: `kind:mode` or `seed:civ-run` args, `out=<png>`), `view_at.gd` (teleport and screenshot, the camera stays where it is put even in the air: `x,y,z>x,y,z` or `site0+dx,dy,dz>site0`, prints FPS), `stats.gd` (counts of everything generated + ready-made `from>look` views of the damaged buildings, tunnels, bridges, passages, ladders), `gun_gallery.gd` (our gun models), `one.gd <function>` (runs one selftest function alone, e.g. `street_tests`, `building_tests`, `climb_tests`, `passage_tests`), `perf_probe.gd` (physics / script ms per frame at a few spots). `view_at.gd` also prints frame / script / physics ms, draw calls and primitives; run it with and without `LETHE_PLAIN=1` (skips the whole war-torn layer) to see what the new content costs. The machine's own load makes single FPS numbers noisy: compare medians of several runs.
Also: `chase_run.gd` (the part-two selftest sections alone: sets the story on ESCAPE INTO THE LANES, about a minute), `chase_probe.gd` (the neighbourhood: lane mouth, paths, pipes, objectives), `chase_shots.gd out=<dir>` (PNGs: lane, drainpipe, gate, roof edge over the circle, the wounded left-handed view), `lookout_debug.gd` / `esc_debug.gd` (why a fire escape does not fit / walk up the first one), `perf_probe.gd` spot "court" (`LETHE_NOCOURT=1` = empty courtyard), `lander_probe.gd` (lookout roof + its way up, lander, story spots), `lander_shots.gd` (the descent seen from the roof: PNGs), `sniper_view.gd` (LR-9 viewmodel and scope on the balcony: PNGs), `view_at.gd lander guards ...` (lands the craft / spawns the ten guards first), `one.gd a,b,c` (several selftest functions in a row), `story_probe.gd` (prints the tram, stalls, first lane, lone soldier, body spots, roles), `civ_probe.gd` (meshes / surfaces of a few civilians). Perf env flags: `LETHE_NOVEIL=1` (old procedural sky), `LETHE_CIVILIANS=<n>` (override `Main.CIVILIAN_COUNT`), `LETHE_NOROUTEDEAD=1` (no bodies along the way home); `perf_probe.gd calm=1` freezes enemies and civilians (isolates rendering).
`tests/selftest.gd` (takes a few minutes: it runs in real time at 120 ticks) runs in the real scene tree under `--headless --fixed-fps 120` and prints PASS / FAIL for: the start (entrance, pistol + knife only), spawn, city layout / path finding / spawn weights, battle sites and their level of detail, the closed border, the mission objectives, the Institute / home / cellar / park (routes, doorways, stairs, landing area, balcony), checkpoints (death, restore, exact loadout), soldier shooting / sneaking / losing track, physics, shooting, AI, loot and loadout, and (the last sections) the war-torn city: time of day, the clear x = 0 / z = 0 band, kerbs, tree / car / obstacle counts, building variety and damage, ladders, bridges, falling, crouch passages, pass-through buildings. The whole run takes 8 to 15 minutes; each check line ends with the elapsed seconds. Do not run other heavy Godot instances while it runs: timing-sensitive checks (stealth, shooting) can fail or crawl. Early on it parks every enemy beyond the east border and moves the player to the central junction. The headless renderer is a dummy: it prints harmless `mesh_get_surface_count` errors; use the screenshot script for anything visual.
- Selftest size: 15 `*_tests` / `*_checks` functions and about 570 `check(` lines in `tests/selftest.gd` (about 4,270 lines); the old text said "about 100 scripted checks" (OUTDATED).
- Entry points in `main.gd`: `--selftest` (runs tests/selftest.gd), `--shots` (tests/screenshots.gd), `--script <res path>` (any script with `run(main)`), `--sandbox` (sandbox mission).
- Other tool scripts in tests/ that the old text did not describe: `perf_battle.gd` (battle profile: `-- --script res://tests/perf_battle.gd [secs=24] [out=<json>] [shots=<dir>] [calm=1]`; the player stands 22 m from the central-avenue battle site, invulnerable, fires 8 shots a second and throws a grenade at 6 / 12 / 18 s; reports frame ms and script ms per section via `Prof`), `perf_renderers.ps1` (+ `perf_renderers.json`: perf_probe under gl_compatibility, mobile and forward_plus, interleaved runs, `-Runs 3 -Frames 400 -Modes calm,live`), `menu_shot.gd` (`out=<png>`: screenshot of the pause menu), `screenshots.gd` (views for visual review, run by `--shots`).

## Performance tooling (autoload `Game`, hud.gd, tests/perf_*)
- `Game.gpu` {name, vendor, type, driver, method, os, godot} is filled at startup (`_probe_gpu`) and printed as `[gpu] ...`; `Game.gpu_is_nvidia` false -> push_warning and a ONE-TIME orange warning in the pause menu (`HUD._show_gpu_warning`, remembered per adapter name in settings.cfg `gpu_warned`). Adapter `type` reads "other" under GL Compatibility: go by the name. README has the "Which GPU" section; `--gpu-index` only works on Forward+/Mobile, NOT here.
- Hitch detector in `Game._process`: a frame over `HITCH_MS` 25 ms is printed `[hitch] t= ms tags pos`, kept in `Game.hitches` (300 newest), summed in `Game.hitch_stats`, appended to `user://hitches.log`. `Game.mark(tag)` tags the frame being worked on (first use shows `(first)`); marks exist for shot, explosion, enemy_spawn, enemy_wake, enemy_death, checkpoint_capture / restore, pickup_spawn, fire_nodes, site_lod, pause. Frames under 3 s get `warmup`, unexplained ones `untagged`. Add a `Game.mark` wherever a first-use or burst cost could land.
- `tests/perf_baseline.ps1` (one command): 3 runs of `perf_probe.gd` with the war-torn city + 3 with `LETHE_PLAIN=1` (`LETHE_SEED` fixes the soldiers' places), merged by `perf_merge.gd` (median of run medians) into `tests/perf_baseline.json` + a table. Spots: lobby, avenue (Institute avenue), site70 (central avenue battle site), fire (burning building), roof (tallest reachable roof), cellar, sky (straight up the central avenue at the wound and landers); windowed 1280x720, vsync off, default quality; per spot median / p95 / p99 / max frame ms, script ms, physics ms, draw calls, primitives, objects, render cpu / gpu ms. `perf_ablate.gd spots=<run json>` switches ONE thing off at a time (enemy AI, enemies hidden, civilians, fires, sites, shadows, lights, particles, MultiMesh scenery, physics 60 Hz, render scale, view distance) and prints the ms saved (noise about +-5 ms; order effects exist). The `TIME_PHYSICS_PROCESS` monitor reads high and does not add up with frame ms: trust frame ms and the ablations.
- `Prof` (scripts/prof.gd): poor man's profiler for the perf scripts. `Prof.on` is false in the game; `tests/perf_battle.gd` turns it on. Call sites look like `var p0 := Time.get_ticks_usec() if Prof.on else 0` ... `if Prof.on: Prof.add("enemy.sense", p0)`. Sections nest, so the sums are per section, not additive.
- `AiBudget` (scripts/ai_budget.gd): global per-tick budget for AI physics rays (`RAYS_PER_TICK` 12) and A* requests (`PATHS_PER_TICK` 1); Main calls `new_tick()` once per physics tick; a refused agent tries again next tick; counters `rays_total`, `rays_denied`, `paths_total`, `paths_denied` are for the perf tools.
- F3 overlay: `PerfOverlay` (scripts/perf_overlay.gd), see the layout in [architecture.md](architecture.md); the README has the user-facing text.
